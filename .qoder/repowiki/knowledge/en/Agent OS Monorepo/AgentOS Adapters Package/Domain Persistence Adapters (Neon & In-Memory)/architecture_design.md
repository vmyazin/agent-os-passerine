The module exposes two interchangeable implementations of `@agentos/core`'s `DomainRepository`: `NeonDomainRepository` in `neon-repository.ts` (PostgreSQL via `@neondatabase/serverless` + `drizzle-orm/neon-http`) and `InMemoryDomainRepository` in `in-memory.ts` (process-scoped `Map`s). Both implement the same contract so they can be swapped via a `RepositoryFactory` used by shared test suites. Shared infrastructure is split into focused files: `schema.ts` declares all Drizzle tables/enums/constraints; `row-mapping.ts` provides per-table selection sets and `mapXxxRow` functions that normalize driver values to domain types; `validation.ts` contains assertion helpers for domain invariants; `pagination.ts` enforces bounded list limits; `errors.ts` defines domain-specific conflict errors (`EventFingerprintConflictError`, `IdempotencyConflictError`, `StaleConfigurationError`, `EventSequenceConflictError`); `database-config.ts` validates `DATABASE_URL`. The public surface is re-exported from `index.ts`, which only exposes the repository classes and error types. Cross-cutting concerns like cursor-based pagination (`afterTimestamp` / `bytewiseText`), JSONB handling (`jsonbValue`/`optionalJsonbValue`), and unique-constraint detection are centralized as private helpers inside each repository implementation.
