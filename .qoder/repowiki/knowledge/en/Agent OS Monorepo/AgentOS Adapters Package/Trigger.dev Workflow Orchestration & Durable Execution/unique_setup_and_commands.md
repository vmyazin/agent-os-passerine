Production handlers are constructed lazily via `createLazyProductionFeatureWorkflowTaskHandler()` so Trigger's task discovery/build phase stays pure; secrets like `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, and `GITHUB_SELECTED_REPOSITORIES_JSON` are only read when the first workflow actually runs. Feature roles must be configured with separate agents and environments, and the verification role is constrained to Bash-only with no MCP/network access.
