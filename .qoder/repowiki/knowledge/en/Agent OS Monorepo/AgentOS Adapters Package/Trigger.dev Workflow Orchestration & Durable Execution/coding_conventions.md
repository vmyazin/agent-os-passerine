- Every external side-effect is modeled as an effect record with a stable key, input fingerprint, owner ID, and lease version, and is always claimed via `claimEffect` before being mutated — used consistently across workflow steps, outbox intents, and runtime session management.
- All cross-module data contracts are validated with strict Zod schemas at process boundaries (task payloads, artifact inputs/outputs, goal progress records, publication results) before being trusted by downstream logic.
- External SDK dependencies are isolated behind frozen factory functions returning interfaces (`createTriggerSdkBoundary`, `createTriggerApprovalWaiter`, `createTriggerWorkflowDispatcher`) so tests can inject mocks without touching Trigger types.
- Errors are classified into explicit domain classes (`WorkflowPermanentError`, `WorkflowTransientError`, `WorkflowBudgetExhaustedError`, `FeatureWorkflowTaskTransientError`, `GoalWorkflowTaskTransientError`) to drive retry/dead-letter semantics uniformly.
- Runtime handles are never passed raw across persistence boundaries; they are sealed with AAD derived from `(runId, stepId, role, externalId)` via `handle-sealer.ts` and stored in `runtime-handle-vault.ts` keyed by external reference.
- Concurrent safety is enforced by fenced leases: mutation methods accept `{ ownerId, leaseVersion }` and reject stale owners, applied uniformly in `InMemoryWorkflowCheckpointStore` and mirrored in the Postgres implementation.
