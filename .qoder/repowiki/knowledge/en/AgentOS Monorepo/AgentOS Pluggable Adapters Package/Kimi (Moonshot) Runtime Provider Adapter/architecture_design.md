The module implements the `RuntimeProvider` interface from `@agentos/core` via `provider.ts`, which owns session lifecycle (`start`, `events`, `send`, `cancel`, `collectOutput`, `usage`, `cleanup`) and exposes a fixed set of tools (`bash`, `read`, `write`, `edit`, `submit_result`, plus conditional `artifact_put`/`artifact_get`). Session state is held in an internal `KimiSession` object protected by a per-session Promise-based mutex so tool calls, `observeCommand`, and cleanup never race. The loop coordinator `loop.ts` drives the request/response cycle against a pluggable `KimiTransport` (default HTTP to `https://api.moonshot.ai/anthropic/v1/messages`), accumulating messages until the model emits `submit_result` or the turn limit is hit. A `KimiSandbox` (sandbox.ts) isolates each session in a tempdir under `sandboxRoot`, enforcing path confinement, symlink resolution, read size limits, and bounded `execFile` output buffers; it also executes bash commands with a minimal env that deliberately omits secrets. `access.ts` provides an in-process `KimiLocalAccessStore` that stages files and credentials behind opaque ids for local deployments, while `from-env.ts` wires environment variables (`KIMI_API_KEY`, `KIMI_BASE_URL`, `AGENTOS_KIMI_SANDBOX_ROOT`) into a ready-to-use provider. `types.ts` centralizes the shared shapes (`KimiMessage`, `KimiContentBlock`, `KimiTransport`, `KimiToolExecutor`, `KimiLoopResult`) that decouple the loop, transport, and provider layers. All configuration validation throws a domain-specific `KimiRuntimeProviderError`; transport failures throw `KimiTransportError`. Session IDs are derived deterministically via HMAC over `runId`+`stepId` using an `ownershipSecret`.
