The module is organized around a small set of cohesive adapters that are wired together by `service.ts` into a `TrustedGitHubPublisherService` exposing `publish`, `cancel`, and `status`. `publisher.ts` implements the core state machine (`claimed` → `blobs_created` → `tree_created` → `commit_created` → `ref_created` → `pr_created` → `succeeded`/`cancelled`) with checkpointed progress stored via `PublicationStore`; each phase is guarded by authorization re-verification and base-SHA staleness checks. `postgres-store.ts` provides the `PublicationStore` backed by Neon Serverless (`@neondatabase/serverless`) calling stored procedures `agentos_claim_publication` / `agentos_save_publication` for optimistic-concurrency control via a `revision` field, plus read-only `publication_records` / `publication_events` tables. `github-app.ts` (referenced from imports) supplies `GitHubInstallationClientFactory` and `GitHubReadOnlyClientFactory` scoped per repository installation; `types.ts` declares the client interfaces, `PublicationRecord`, `PublicationEvent`, and scope types separating write vs read permissions. `source-snapshot.ts` and `repository-head.ts` provide read-only ingestion paths that walk a GitHub tree under strict size/path/symlink/submodule limits and emit canonical JSON bundles to an `ArtifactStore`. `repository-allowlist.ts` exposes helpers for selecting and validating repository bindings. All public entry points are re-exported through `index.ts`, which hides internal modules and exposes only stable contracts (`createTrustedGitHubPublisherService`, `createTrustedSourceSnapshotIngestor`, `createTrustedRepositoryHeadResolver`). Dependency direction: `service` → `publisher` → (`github-app`, `postgres-store`, `errors`) with `types.ts` as the shared contract consumed by both publisher and store.
