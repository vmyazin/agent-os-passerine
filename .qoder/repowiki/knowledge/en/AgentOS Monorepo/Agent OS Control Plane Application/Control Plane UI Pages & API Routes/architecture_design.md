The module is organized as a Next.js App Router application under `apps/control-plane/app/`. The root `layout.tsx` defines an `app-shell` with an `app-rail` sidebar (navigation, sign-out, status) and loads page-level session via `readPageSession()` alongside rail counts via `fetchRailCounts()` in parallel. Feature areas (`projects`, `runs`, `inbox`, `configuration`, `setup`) each have a folder with a `page.tsx` async server component that calls `controlPlaneService()` from `src/application/runtime` to fetch data and composes shared UI primitives from `src/ui/*`. A parallel `app/api/` tree mirrors these features plus auth flows (`auth/github`, `auth/local`, `auth/logout`) and internal utilities (`internal/artifacts/cleanup`, `internal/workflows/reconcile`, `health`, `ready`, `test/seed`). Every API handler uses the shared `handleApi(request, { authorize, output }, handler)` wrapper from `src/http/api`, which centralizes authentication via `requireApiAuthentication`, Zod-based request/response validation through schemas in `src/http/contracts`, and error serialization. Auth state is cookie-based using `OAUTH_COOKIE` and `SESSION_COOKIE` set by the GitHub OAuth callback. Dynamic path parameters are sanitized through `boundedPathId` before being passed into domain services. Global error/loading states are provided by root-level `error.tsx` (client component) and `loading.tsx`.
