Each directory under `apps/control-plane/app/api/` maps to a Next.js App Router endpoint with one `route.ts` per HTTP verb (GET/POST), using dynamic segments like `[id]` for resource paths. Every authenticated route follows a uniform shape: it imports `handleApi` from `../../../src/http/api`, supplies an `authorize` function that calls `requireApiAuthentication`, declares request body/output schemas via Zod from `../../../src/http/contracts`, and delegates business logic to `controlPlaneService()` from `../../../src/application/runtime`. Read-only endpoints such as `health` and `ready` bypass authentication and return plain JSON responses. Internal/cron routes under `internal/` opt into Node runtime (`runtime = 'nodejs'`, `dynamic = 'force-dynamic'`) and delegate to shared cron handlers (e.g. `createArtifactCleanupCronHandler`). The `setup/apply` route is a special case that parses YAML server-side using `@agentos/core` helpers (`loadAgentOsConfig`, `canonicalConfigJson`, `canonicalConfigHash`) before invoking the service, enforcing size limits via `MAX_CONFIG_APPLY_BODY_BYTES`. Dependency direction is strictly inward: routes depend on `src/http/*` (request handling, auth, contracts) and `src/application/*` (service layer); no cross-route imports exist.
