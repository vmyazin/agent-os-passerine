The module is organized into four cooperating layers with a strict dependency direction: `config/` loads `agentos/example.yaml` into typed metadata; `persistence/repository-factory.ts` selects between an in-memory store and Neon via the `DomainRepository` interface from `@agentos/adapters`; `application/control-plane-service.ts` defines the core `ControlPlaneService` class that orchestrates project resolution, configuration application, run lifecycle, inbox projection, approval expiry logic, and artifact dispatch through injected ports (`WorkflowDispatchOutbox`, `IdGenerator`, optional `repositoryHead`, `artifacts`); `http/api.ts` wraps route handlers with a Zod-based `handleApi` contract that enforces body size limits, JSON parsing, authorization hooks, output validation, and uniform `{error:{code,message}}` error responses by catching `AuthError`/`ServiceError`. Cross-cutting concerns include secret redaction via regex patterns on all user-visible strings, deterministic project identity derived from binding keys with legacy single-project migration, concurrency-bounded fan-out (`DIGEST_QUERY_CONCURRENCY=8`) for inbox digest queries against Neon's per-query connection model, and idempotency keyed by `(kind, idempotencyKey)` persisted through the repository. Tests co-locate with sources (`*.test.ts`) and use the test-only `resetRepositoryForTests()` helper to clear the global repository singleton.
