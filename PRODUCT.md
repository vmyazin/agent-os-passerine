# Product

## Register

product

## Users

One trusted operator uses Agent OS while reviewing and supervising automated
software work. They need to scan runs, answer agent questions, approve narrowly
scoped actions, and inspect evidence from desktop or mobile without losing the
thread of the active run.

## Product Purpose

Agent OS turns a feature request into reviewed artifacts and a tested draft pull
request while keeping approvals, budgets, credentials, and publication authority
outside model sessions. Success means the operator can understand what needs
attention, make a safe decision quickly, and retain a reconstructable audit trail.

## Brand Personality

Calm, precise, trustworthy. The product should feel like a focused operations
desk: technically credible, restrained, and direct without becoming sterile.

## Anti-references

- Generic SaaS dashboards made from isolated cards and oversized metrics.
- Chat interfaces that hide scope, provenance, or decision context.
- Dense developer consoles that expose raw data before the human-readable task.
- Decorative AI imagery, gradients, glass effects, and saturated status color.

## Design Principles

1. Put the next operator decision first.
2. Preserve context between a request, its run, and the resulting action.
3. Use progressive disclosure for hashes and machine-oriented evidence.
4. Let familiar product patterns reduce learning cost.
5. Reserve color for selection, focus, and semantic state.

## Accessibility & Inclusion

Target WCAG 2.2 AA. All workflows must remain keyboard accessible, retain visible
focus, work without color as the sole status signal, support 390 px touch
viewports, and honor reduced-motion preferences.
